# 恢复与验证

在 Agent 阻塞、超时、越界、冲突、验证失败，或父 Agent 准备最终扇入时读取。

## 恢复阶梯

1. **澄清**：发送缺失事实、失败输出、接口决定或更窄的完成条件。
2. **纠偏**：明确停止越界方向，保留有效成果，只处理剩余目标。
3. **替换**：确认原 Agent 无法恢复后关闭它，把收窄且包含已知事实的任务交给新 Agent。
4. **升级**：只有涉及产品决策、破坏性操作、凭据、费用或无法从现有材料判断的外部事实时询问用户。

同一阻塞先尝试一次明确纠偏；不要连续创建多个 Agent 重复碰撞同一问题。

## 常见故障

### Agent 请求用户输入

- 不替用户批准敏感操作。
- 若父 Agent 已有答案，直接发送；否则把最小问题升级给用户。
- 依赖未满足时暂停相关分支，继续其他独立工作。

### 写入越界或冲突

- 立即停止冲突 Agent 的后续写入。
- 比较实际 diff，保留唯一正确来源。
- 共享文件由父 Agent 或预先指定的唯一所有者处理。
- 重新切分边界后再继续；不要让两个 Agent“协商着同时改”。

### 验证失败

- 区分 Agent 局部失败、集成失败和环境失败。
- 把失败命令、关键输出与期望行为发给最接近根因的所有者。
- 只重跑受影响检查；最终仍需运行覆盖集成面的验证。

### 超时或无响应

- 首先判断父 Agent 是否真的依赖结果。
- 若不依赖，继续本地工作并等待下一个事件。
- 若依赖，获取一次状态；给出明确完成条件或收窄任务。
- 确认无法恢复后再替换，不做高频轮询。

## 扇入检查清单

- [ ] 每个实现 Agent 的实际改动均在允许范围内。
- [ ] 没有两个 Agent 修改同一共享文件、schema、锁文件或生成物。
- [ ] 调查结论包含原始证据，推断已明确标注。
- [ ] 父 Agent 已审查实际 diff 或产物，不只看摘要。
- [ ] 局部验证结果可复现，未运行项有原因。
- [ ] 集成测试、类型检查、构建或格式检查已按任务需要运行。
- [ ] 失败已聚焦修复并重跑受影响检查。
- [ ] 无意外文件、遗漏依赖、未经授权的外部操作或隐藏 Worker。
- [ ] 所有不再需要的 Agent 已关闭。
- [ ] 最终报告包含拓扑、角色、结果、验证和残余风险。
