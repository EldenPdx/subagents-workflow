# 调用参数与任务契约

仅在用户指定编排参数，或父 Agent 即将首次委派时读取。

## 参数解释

- `topology=auto`：按依赖和所有权自动选择最小拓扑。
- `agent_count=N`：若用户说“使用 N 个 Agent”，应尽量形成 N 个有意义角色；没有足够独立边界时说明原因，不制造重复任务。
- `max_agents=N`：并发上限，不是必须填满的配额。
- `write_scope`：每个写入 Agent 的唯一文件或目录集合。范围重叠时先重新切分，无法切分则改为串行。
- `validation`：优先使用仓库已有命令；没有时选择能证明该任务关键不变量的最小检查。
- `external_orchestrator=explicit-only`：只有用户明确指定外部编排器时才允许切换。

## 委派契约模板

```text
角色：<implementation | investigation | review | verification>
目标：<一个可独立验收的结果>
限定任务：<必须完成的具体工作>
范围外事项：<不要顺手扩展的内容>
读取入口：<先读的文件、符号、测试或原始材料>
允许写入：<唯一文件或目录范围；只读任务写“无”>
禁止写入：<共享文件、其他 Agent 范围、生成物等>
依赖和启动条件：<无，或依赖哪个已完成结果>
已确认决策：<接口、约束、兼容性和用户要求>
预期产物：<代码、测试、证据、分析或评审结论>
验证命令：<聚焦且可运行；没有则写明原因>
完成汇报：<状态、摘要、改动文件、验证、风险、集成动作>
```

契约中的所有占位符必须替换为实际值。

## 角色示例

### 实现 Agent

```text
角色：implementation
目标：实现 API 输入校验并保持现有响应格式
限定任务：修改请求 schema、处理器与对应单元测试
范围外事项：不调整认证、数据库 schema 或公共错误码
读取入口：src/api/request.ts、src/api/handler.ts、tests/api.test.ts
允许写入：src/api/request.ts、src/api/handler.ts、tests/api.test.ts
禁止写入：package-lock.json、src/auth/**、migrations/**
依赖和启动条件：共享错误类型已由父 Agent 确认
已确认决策：无效输入返回现有 INVALID_ARGUMENT 结构
预期产物：实现与聚焦测试
验证命令：npm test -- tests/api.test.ts
完成汇报：状态、摘要、改动文件、验证、风险、集成动作
```

### 调查 Agent

```text
角色：investigation
目标：定位间歇性超时的最可能根因并给出证据链
限定任务：追踪调用路径、日志与超时配置，不修改代码
范围外事项：不提出大规模重写，不操作生产环境
读取入口：错误日志、客户端入口、重试与超时配置
允许写入：无
禁止写入：整个工作区
依赖和启动条件：无
已确认决策：结论必须区分事实、推断和未知项
预期产物：按置信度排序的根因、证据和最小复现建议
验证命令：无；只读调查
完成汇报：状态、主要发现、证据位置、风险、建议动作
```

### 验证 Agent

```text
角色：verification
目标：独立验证实现是否满足需求与回归边界
限定任务：检查 diff、运行指定测试并报告失败
范围外事项：默认不修改实现
读取入口：需求、git diff、相关测试与配置
允许写入：无
禁止写入：整个工作区
依赖和启动条件：实现 Agent 已完成
已确认决策：发现问题时给出文件和可复现步骤
预期产物：通过/失败结论、证据、残余风险
验证命令：<集成检查命令>
完成汇报：状态、结论、命令结果、风险、建议动作
```

## 完成汇报模板

```text
状态：completed | blocked
角色与目标：...
主要结果：...
改动文件：... | 无
验证：<命令与结果> | 未运行及原因
风险/阻塞：... | 无
建议的集成动作：...
```
