# 运行时适配

仅在宿主工具名称不同、原生委派能力缺失，或用户明确要求外部 Orchestrator 时读取。

## 能力映射

工作流依赖的是语义能力，不是固定工具名：

| 语义能力 | Codex 原生工具 | 期望行为 |
|---|---|---|
| 创建隔离 Agent | `spawn_agent` | 接收自包含契约，返回可寻址 Agent |
| 发送纠偏或新事实 | `send_input` | 可排队或立即中断当前方向 |
| 等待完成或注意事件 | `wait_agent` | 面向依赖、低频、可设置较长超时 |
| 释放并发资源 | `close_agent` | Agent 不再需要时关闭 |
| 恢复已关闭 Agent | `resume_agent` | 复用相关上下文，而不是重复创建 |

其他宿主若提供等价能力，按同一语义映射。不要依赖某个工具独有的非必要字段。

## Codex 约束

- 子任务使用原生 Subagent 工具，不使用 `create_thread` 创建用户任务。
- 父 Agent 先决定关键路径，不能把下一步阻塞任务委派后立刻空等。
- 代码 Agent 在自己的隔离工作区直接修改文件，并列出完整改动路径。
- `wait_agent` 仅在父 Agent 的下一步确实依赖结果时使用；等待期间继续不重叠工作。
- 完成或放弃的 Agent 用 `close_agent` 关闭；相关后续优先 `resume_agent` 或 `send_input`，避免重复创建。

## 没有原生 Subagent 工具

选择 `direct`：

1. 父 Agent 串行完成任务；
2. 保留同样的计划、所有权和验证纪律；
3. 明确说明运行时不支持真实并行；
4. 不通过 Shell、后台进程或新用户任务伪造隐藏 Agent。

这属于正常降级，不是失败。

## 外部 Orchestrator

只有以下条件之一成立时才考虑：

- 用户明确指定某个外部 Orchestrator；
- 用户明确要求跨会话、长时间后台、异构模型、独立 CLI 或持久审计；
- 宿主无原生能力，且用户在了解代价后明确同意。

切换前确认：

- 工具已安装且当前环境可调用；
- 权限、凭据、费用、沙箱和写入范围得到授权；
- 外部 Worker 不与原生 Agent 同时写同一范围；
- 有停止条件、超时、恢复和最终导入验证方案。

工具不可用或授权不完整时保持 `direct`，不要自行安装未知依赖或绕过审批。
